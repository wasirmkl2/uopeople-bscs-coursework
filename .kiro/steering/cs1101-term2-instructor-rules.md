# CS 1101-01 Programming Fundamentals (Term 2, AY2027-T1) — Instructor Requirements

Course-specific rules confirmed directly by the instructor for this course. These are hard
requirements for every Discussion Forum post, peer reply, and written Assignment in
CS 1101-01. They override any general/default assumption made elsewhere in steering.

## Instructor

**Hussam** — instructor for CS 1101-01 Programming Fundamentals, Term 2 (AY2027-T1).

## 1. Code must be pasted as text — never as a screenshot

Direct instruction from the instructor (paraphrased from his announcement to students):

> Do not use screenshots when submitting code in Discussion Forums or Assignments. Copy and
> paste the code (input) and the program (output) as text directly into the post or
> assignment.

Concrete requirements that follow from this:

- **Never** submit, generate, or recommend an image/screenshot of code or of terminal output
  for this course. No `.png`/`.jpg` of an IDE window, no screenshot of a console.
- **Paste the code as real text**, inside a fenced code block (```` ```python ````) for
  discussion-forum markdown, or as monospaced text in a `.docx`.
- **When output is shown, paste it as text too** — same rule, no screenshots of a console.
- **Do not over-read this as a requirement that every submission include program output.**
  The instruction is about *format* (text, not images); the "(input)" and "(output)"
  parenthetical describes how to paste each when both are present. Whether output is needed
  at all is decided by the specific assignment prompt and rubric, not by this note. Mistake
  made once in this project: treating this note as meaning a discussion post showing only
  function definitions "does not satisfy" the instructor, when that unit's rubric asked only
  for code showing arguments and return values. Check the rubric first.
- Judgement call to apply: include a short sample run when it genuinely adds something the
  rubric rewards (e.g., the rubric asks what values functions *return*, and a run makes those
  return values concrete), or when the prompt asks for a working program. Skip it when the
  prompt only asks for a code illustration and a run would just add bulk. Since code and
  output don't count toward the word limit in this course (Section 2), including a run is
  cheap — but "cheap" is not the same as "required."
- **Any output shown must be the real, verified output of actually executing that exact
  code**, never a hand-written approximation of what it would probably print. Run the code
  and copy the actual result (see the no-fabrication rule in `assignment-writing-rules.md`
  Section 1).

## 2. Code blocks do NOT count toward the word count

Confirmed for this course: **the instructor does not count code blocks as words.** For any
CS 1101-01 assignment or discussion post with a stated word range (e.g., 250–500 words for a
discussion post):

- Count **prose only** — the explanatory sentences and paragraphs.
- **Exclude** fenced code blocks, the sample-run driver code, and the pasted program output
  from the count.
- Also exclude the reference list, per the assignment instructions' own wording.
- Still apply the standing buffer rule from `assignment-writing-rules.md` Section 3: land
  20–30 words below the stated ceiling on the **prose** count, and recompute after every
  edit.
- Practical consequence: there is no need to sacrifice prose quality to "make room" for a
  code block in this course, and no need to shrink or strip docstrings/comments from code to
  save words. Write the code clearly and completely, then spend the full word budget on the
  explanation.
